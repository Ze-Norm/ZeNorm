# ZeNorm

Local web workspace: a person adds a project (a git repository), plans changes in maps with a planning agent, and gets them delivered as reviewed branches ready to merge.

## Packages

All packages are `@zenorm/<dir>`, ESM, exporting TypeScript source, except the published `@ze-norm/cli`. Workspace imports are limited to each package's `dependencies` (pnpm strict resolution); "→" lists what each may import.

- `packages/contracts` → none. Zod schemas, oRPC contract, `Result`, error-code unions, instance config schema, seam signatures, `DeliveryExecutor`.
- `packages/db` → contracts. Drizzle schema, migrations, `openDatabase`, `migrateDatabase` (its migrations folder passed in; `MIGRATIONS_FOLDER` is the repository's; a database holding a migration the folder does not ship is refused `database_newer_than_build`), `checkDatabaseFile` (the same comparison, read-only), change-feed triggers (`installChangeFeed`).
- `packages/core` → contracts, db. Domain functions (projects, maps, question rounds, specs, ticket sets, delivery runs, holds/waits, reconciliation), git and check commands, `write` (every write names its Actor), after-commit `ChangeBus`, the seams (`seams.ts`, set per database with `setSeams`). No HTTP, no React.
- `packages/agent` → contracts. The `claudeCode*` adapters: every Claude Code CLI session behind the planning, spec, tickets and delivery ports. Sessions read `<skillsDir>/*/SKILL.md` at run time, from the skills folder the entry passes in (`SKILLS_DIR` is the repository's `skills/`). Each `claude` process runs in its own process group, with a session record in `<dataDir>/sessions`. No HTTP, no database, no `console`.
- `packages/server` → contracts, core, db, plugin-sdk. Hono app, behind a request guard registered before every route (refuses a Host that is not the config's `server` host:port, `localhost`, `127.0.0.1` or `[::1]` on that port with 403 `host_not_allowed`; on `/rpc` also a foreign or `null` Origin with 403 `origin_not_allowed` and a POST not declared `application/json` with 415 `content_type_not_json`; each refusal is logged; tests that call `app.request` set `Host` explicitly): `/rpc/*` (identity, project resolution and access check on every procedure), `/healthz`, `/events` (SSE), `/plugins/<id>/`, static web build. `plugins.ts` runs plugin startup checks, composes seams and subscribers, and holds the executor registry `delivery.executor` picks from. In-process planning and delivery runners.
- `packages/web` → contracts, plugin-sdk. Vite, React, TanStack Router (code routes) and Query, Tailwind v4, shadcn (`src/components/ui`). `createWebApp({ plugins })` lives at the `@zenorm/web/app` entry; `.` stays Node-safe for `webDistDir`.
- `packages/plugin-sdk` → contracts. `definePlugin`, `defineWebPlugin`, manifest, contribution and slot types. `hono` and `react` are type-only peers.
- `apps/zenorm` → contracts, agent, db, server, web (only `webDistDir`). `main.ts` loads config, migrates, wires the agent, registers executor `"local"`, composes no plugins. Every entry passes in its web build, skills folder and migrations folder (`ZeNormAssets`); `main.ts` passes the repository's (`source-assets.ts`). `serveZeNorm`, `startAndListen`, `startZeNorm`, `localExecutor` and the e2e helpers are exported for `apps/zenorm-example` and `apps/cli`. Playwright in `e2e/`, one server per worker (`e2e/worker-server.ts`).
- `examples/plugin-example` → plugin-sdk, contracts. Exercises every extension point, including the `example` executor. `examples/bad-plugins/` has one bad plugin per startup error code.
- `apps/zenorm-example` → contracts, server, web, plugin-sdk, the example plugin, apps/zenorm. The app composed with the example plugin. Playwright on port 4650 runs after `apps/zenorm`'s, under the same lock.
- `apps/cli` → contracts, agent (the sign-in status read and login), apps/zenorm, web (only `webDistDir`, at build time). The published `@ze-norm/cli` package and its `zenorm` command (`init`, which writes a config from one model choice after Claude Code's sign-in; `run`, which also refuses a signed-out Claude Code, a database newer than the build, a data folder another ZeNorm holds (`data_dir_in_use`) and a host and port it cannot bind (`server_port_in_use`): the first before anything is migrated or swept, the second before any run is marked interrupted or relaunched; and `doctor`, which runs every check read-only and reports each with its code; every command first refuses native Windows and Node older than 26.11.1, and reads its config from `--config`, `ZENORM_CONFIG` or `~/.config/zenorm/config.json`; `--help` on the program or a command and `--version` exit 0; any other command line is `arguments_invalid`). The command layer is commander with `@commander-js/extra-typings`, and `COMMANDS` in `src/commands.ts` is the one command table: each entry carries its name, description, options and the `Command` it runs, so adding a command is adding one entry, and any list of command names is derived from it (a test compares the help's commands with it). Commander's traps: set the exit and output hooks (`exitOverride`, `configureOutput`) before adding any command, since a command copies them only when it is added; help-command settings (`helpCommand(false)`) are not inherited by a command group, so set them on each one; check option values with a value parser (`argParser`), not choices; refuse a repeated option in that parser (it gets the previous value); and never use a library default (`.default()`, a default argument): defaults live in code. `pnpm --filter @ze-norm/cli build` bundles it with esbuild into `dist/zenorm.js` and copies `skills/`, the migrations and the web build beside it; better-sqlite3 is its only runtime dependency, every workspace import and both commander packages a devDependency the bundle inlines. The `pack` turbo task (`scripts/pack.ts`, after `build`) writes the published manifest (no scripts or devDependencies, `catalog:` pinned) and the README with its relative links made absolute at the `v<version>` tag (npm would resolve them under `apps/cli/`), and packs `pack/<name>.tgz`; `scripts/smoke.ts` installs that tarball with npm outside the repository, checks its only dependency, `--help`, `--version` and an unknown option's `arguments_invalid`, and drives `doctor`, `run` and one map to a passed delivery with the stand-in claude. Composes no plugins.

`skills/` and `CONTEXT.md` are outside the workspace and every check. `.scratch/`, `docs/` and `prototypes/` are gitignored for local planning files.

## Rules

- No silent defaults. Missing config or data is a coded error, never a fallback, so a gap fails at its source, not later as a wrong value: no `??`, `||`, `??=` or `||=` with a literal or empty `[]`/`{}` on the right, no Zod `.default()` or `.catch()`. `pnpm lint` enforces it. Every `eslint-disable` names its rules and gives a `-- reason`.
- Expected failures return a `Result` with a stable error code; only programmer errors throw. Tests assert codes, never message text.
- Use shadcn components over bespoke Tailwind.
- `CONTEXT.md` glossary terms are the identifiers (`Project`, not `Repo`).
- Server-side code runs on Node type stripping: relative imports end in `.ts`, erasable syntax only (no enums, namespaces or parameter properties). `.tsx` only in the web entries (`packages/web`, `examples/plugin-example`, `apps/zenorm-example`).
- No `console` outside the apps (`apps/zenorm`, `apps/zenorm-example`, `apps/cli`); packages log through the `log` function the app passes in.

## Running

- `pnpm install`, then `pnpm exec playwright install chromium` once.
- `ZENORM_CONFIG=/path/to/config.json pnpm dev` serves the app; `pnpm dev:example` serves the example composition (config needs `plugins.example`).
- Config requires `plugins` (`{}` for none) and `delivery.executor` (`"local"` or a plugin's). No defaults, but one optional key: `agent.fastMode` and `delivery.fastMode` (absent is off) turn on Claude Code's fast mode through `--settings`, and need Opus models.
- `ZENORM_LIVE_CLAUDE_PATH="$(command -v claude)" pnpm --filter @zenorm/agent test:live` runs the opt-in live test (outside `pnpm check`).
- `pnpm check` is the gate (prettier, then `turbo run typecheck lint test e2e`). `pnpm format` fixes formatting.
- `pnpm exec turbo run pack --filter=@ze-norm/cli && pnpm --filter @ze-norm/cli smoke` runs the install smoke test (outside `pnpm check`: it installs from the npm registry). CI's `check` workflow runs it on Linux beside the check.
- Releases are CI only: pushing a `v<version>` tag matching `apps/cli/package.json` runs the `publish` workflow, which publishes the packed tarball with npm provenance once the check and the smoke test pass. It authenticates by npm trusted publishing (no token; the package refuses tokens). CI runs on Linux only, without e2e: run `pnpm check` locally before pushing.
